# Android 工程启动说明

更新：2026-10-31。当前为原生 Android 工程骨架，只有启动页；接单管理、数据保存、导入导出、账号和服务端功能均尚未实现，不可用于真实业务数据。

## 环境与验证结果

- JDK：Microsoft OpenJDK 17；Android SDK 路径：`D:\CODE\android-sdk`。
- 已安装命令行工具、Android API 36 平台、Build Tools 36.0.0 和 Platform Tools；SDK 安装包由腾讯云镜像下载，并与 Google 官方发布的哈希或官方索引校验值核对一致。
- Gradle 9.4.1 已通过官方 SHA-256 校验；项目 Wrapper 使用腾讯云镜像，并保留官方发行包 SHA-256 验证。已将已校验发行包放入本机 Wrapper 缓存。
- 工程依赖优先使用阿里云 Maven 镜像，保留 Google、Maven Central 等官方源作为回退；首次下载速度受网络影响。
- 通过项目自带命令 `gradlew.bat --no-daemon :app:assembleDebug` 成功构建。构建工具版本：Android Gradle Plugin 9.2.0、Gradle 9.4.1、Kotlin Compose 插件 2.2.10、Compose BOM 2026.03.00、compileSdk / targetSdk 36、minSdk 26。Compose BOM 2026.08.00 所含组件要求 compileSdk 37，已调整为 2026.03.00 并通过构建。
- Debug APK：`app\build\outputs\apk\debug\app-debug.apk`。仅验证编译，ADB 未检测到设备，尚未安装或真机运行。
- 构建过程中提示 `libandroidx.graphics.path.so` 未被剥离调试符号并原样打包，构建成功；这可能增加调试包体积，后续发布构建时再评估。

## 后续构建

1. 确保 JDK 17 和 Android SDK 平台/构建工具可用。项目本机 `local.properties` 已指向 SDK 路径，此文件被 Git 忽略；换机器时需自行配置 SDK 路径。
2. 在项目根目录运行 `./gradlew.bat :app:assembleDebug`。
3. 连接已开启开发者选项及 USB 调试的测试设备，或启动模拟器；通过 `adb devices` 确认后安装并验证 APK 启动。

工程入口为 `app/src/main/java/com/engnotes/artistorders/MainActivity.kt`。后续按既定架构分离 UI、业务与数据层；当前尚未实现数据层。
